# COFRAME — Functional vs. Simulated Disclosure Matrix

Per the BIOS FORGE Hackathon rules, this matrix transparently details the implementation reality of every major system capability within COFRAME.

| System Capability | Implementation Reality | Verification / Proof |
| :--- | :--- | :--- |
| **Two Human Sessions (Alex & Maya)** | **Functional Demo Identity Model**<br>Two distinct identities (Alex: Founder / Decision Owner, Maya: Product Designer). Realtime presence tracks both browser windows. No production JWT/password auth in P0 scope. | Join as Alex in Window 1, Maya in Window 2 (e.g. Incognito). Online status indicator turns green on TopBar in both sessions. |
| **Realtime Presence & Synchronization** | **Functional Realtime WebSocket Engine**<br>FastAPI WebSocket connection (`/ws/{project_id}/{identity_key}`) broadcasts events, requirement edits, section changes, and presence to all connected tabs without manual refresh. | Edit a requirement in Alex's window; Maya's window immediately updates context version and displays the new state. |
| **NOVA (Product Strategist Agent)** | **Functional Provider Adapter with Labeled Fallback**<br>Calls live LLM (Gemini, OpenAI, Claude, OpenRouter) with strict structured JSON output. If API key is not configured or rate-limited, switches to deterministic fallback with `source="cached_fallback"` and visible `SIMULATED FALLBACK` badge. | Proposals display live/fallback origin badge on the card and in raw JSON metadata. |
| **PIXEL (Prototype Engineer Agent)** | **Functional Provider Adapter with Labeled Fallback**<br>Generates structured JSON operations (`set_hero_content`, `set_dashboard_metrics`, `set_approval_queue_config`) adhering strictly to the component contract. Never runs arbitrary unverified code. | Verified against Pydantic validation schema and rendered by the fixed React renderer. |
| **Authoritative Context Pack** | **Functional Persisted Backend Pack**<br>Built from database state (requirements, decisions, section versions, recent events). Stored immutably on `agent_runs.context_pack`. | Inspectable in the Context Inspector tab. Shows exact JSON pack provided to the agent. |
| **Selective Staleness** | **Functional Set-Intersection Engine**<br>Computes `changed_requirement_keys ∩ proposal.affected_requirements`. Proposal A (Audience) becomes STALE when REQ_AUDIENCE changes; Proposal B (Metrics) remains eligible! | Automatic evaluation on `PATCH /requirements`. Plain-language stale reason shown on Proposal A. |
| **Section Conflict Detection** | **Functional Compare-and-Swap Version Check**<br>When Maya manually edits a section, section version increments. Any older proposal with lower base section version becomes CONFLICT. | Manual Hero Edit increments hero to v2; PIXEL Proposal C (based on v1) automatically displays `CONFLICT` badge. |
| **Atomic Apply Engine** | **Functional ACID Transaction**<br>Database transaction (`with_for_update`) rechecks versions, requirements, and permissions. Partial writes are impossible. If one section fails, all roll back. | Proved by `backend/tests/test_backend.py::test_atomic_apply_and_permissions`. |
| **High-Impact Decision Policy** | **Functional Server-Side Rule Engine**<br>Proposals modifying approval policy or roles automatically receive `requires_decision=True` and `assigned_decider_id="alex"`. Maya is denied with HTTP 403. | Step 6 demonstrates Maya blocked from approving; Alex redirects with note; revised proposal approved. |
| **Agent Restart & Recovery** | **Functional Database State Recovery**<br>Closes previous run, builds new Context Pack from persisted project state, and generates authentic recovery summary. | Context Inspector shows new run ID, reconstructed requirements, and offline event count. |
| **Observer Summary** | **Functional Live Synthesis + Rule Fallback**<br>Top-of-screen banner producing What Changed, Why, and What Happens Next, citing source events. | Visible immediately under TopBar. Switches dynamically between Live LLM and Rule-Based engine. |
| **Trusted Prototype Renderer** | **Functional Fixed React Component Suite**<br>`LedgerFlowHero`, `LedgerFlowMetricGrid`, and `LedgerFlowApprovalQueue` render approved JSON data within a dedicated warm-white canvas. | Live interactive rendering on Product Canvas tab. |
| **Deterministic Reset Demo** | **Functional Seed Database Reset**<br>`POST /api/demo/reset` wipes and restores baseline requirements, LedgerFlow sections, versions, and events. | 1-click Reset Demo button in TopBar. |
